# Ontocode CLI 1.1.5

## Changed

- Model selectors now resolve by family instead of fixed versions. A selector
  such as `gemini-flash-high` or `sol` matches the current versioned model in
  the catalog, so built-in roles, the `fast` spawn priority, manager-loop
  candidate checks and memory stage selection keep working across model
  upgrades. Selectors that include a version still match exactly.
- Any `kimi` model is accepted by the Responses proxy and forwarded unchanged.
- Default base instructions add guidance for direct, complete delivery and
  lightweight orchestration.

## Fixed

- `wait_agent` records a rejected sub-agent result as its terminal status and
  waits for new evidence instead of re-reporting the same rejection in a loop.
  A later corrected result replaces the stored rejection.
- Tool exchanges stay valid around hosted and local-shell interleaving, exact
  retries of a full call and output, and calls streamed after earlier outputs.
- Tool handlers never start for calls cancelled at admission or during start
  hooks, and immediate rollback after a completed turn is accepted.
- Managed MITM CA creation is serialized, lives under the session's Ontocode
  home, and reports the chmod fix when its key is too widely readable.
- Removed features in managed requirements are ignored instead of failing.

## Validation

- 1158 focused library tests passed across protocol, core, memories, models
  manager and the Responses proxy.
- Clippy, formatting and scoped source verification passed.

## Distribution

This release provides an unsigned Linux x86_64 binary, installers, the project
plan template and SHA256 checksums. The optional content pack is unchanged.
